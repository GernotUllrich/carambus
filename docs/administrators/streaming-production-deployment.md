## Architecture Overview

### Components

```
Admin Dashboard (Rails Server)
  ↓ SSH
Raspberry Pi (Camera + FFmpeg)
  ↓ RTMP
YouTube Live Stream
  ↓ HTTP
Rails Server (Scoreboard Text Endpoint)
  ↓ Curl (every 1 second)
Raspberry Pi (Background updater)
  ↓ FFmpeg drawtext filter
YouTube Stream (Live Overlay)
```

### Key Files

- **Server**: `app/controllers/locations_controller.rb#scoreboard_text` - Text endpoint
- **Server**: `app/jobs/stream_control_job.rb` - Writes the Pi configuration and starts/stops the service
- **Pi**: `/usr/local/bin/carambus-stream.sh` - Main streaming script
- **Pi**: `/etc/carambus/stream-table-<table_id>.conf` - Configuration (auto-generated by the admin dashboard)
- **Pi**: `/tmp/carambus-overlay-text-table-<table_id>.txt` - Text file for the overlay, in the service's
  private `/tmp` (`PrivateTmp=true`), not visible from an SSH shell
- **Pi**: `/var/log/carambus/stream-table-<table_id>.log` and `…-error.log` - Script and FFmpeg output

`<table_id>` is always the Rails database ID of the table (`Table.id`), never the number from "Tisch 6".

## Admin Dashboard Configuration

### How Admin Dashboard Controls Streaming

The admin dashboard is the **primary control interface** for production streaming. When you use the dashboard:

1. **Configuration stored in database** (`StreamConfiguration` model). Saving does not deploy anything.
2. **Start button** triggers `StreamControlJob`:
   - Generates config file from database settings
   - Deploys to Pi via SSH: `/etc/carambus/stream-table-<table_id>.conf`
   - Executes: `systemctl start carambus-stream@<table_id>.service`
3. **Stop button** executes: `systemctl stop carambus-stream@<table_id>.service`

The job runs inside the Carambus service (`puma-<basename>`, user `www-data`) and only sees that service's
environment (`/etc/<basename>.env`). Two variables from there matter:

- `STREAMING_SERVER_URL` becomes `SERVER_URL` in the Pi configuration, i.e. the address the Pi fetches the
  overlay text from. Without it the job writes `http://localhost:3131`, which is only right if Rails runs on
  the same Pi on port 3131. Set it to `http://<server>:<webserver_port>` and restart `puma-<basename>`.
  Whether it is set on a given server can only be checked there (`sudo grep STREAMING_SERVER_URL /etc/<basename>.env`).
- `RASPI_SSH_PASSWORD` / `RASPI_SSH_KEYS` for the SSH connection (see [Security Notes](#security-notes)).

### Important Parameters

The following database fields control the stream quality. New configurations default to
640x360 @ 30 fps, 1000 kbps (migration `20251231132304`).

| Field | 360p (Low) | 720p (Recommended) | 1080p (High) | Description |
|-------|------------|-------------------|--------------|-------------|
| `camera_width` | 640 | 1280 | 1920 | Resolution width |
| `camera_height` | 360 | 720 | 1080 | Resolution height |
| `camera_fps` | 30 | 30 | 30 | Frames per second |
| `video_bitrate` | 1000 | 2500 | 4500 | Video bitrate in kbps |
| `audio_bitrate` | 128 | 128 | 128 | Audio bitrate in kbps |
| `overlay_enabled` | true | true | true | Enable text overlay |
| `overlay_height` | – | – | – | No effect in text overlay mode (see below) |
| `raspi_ip` | 192.168.x.x | 192.168.x.x | 192.168.x.x | Pi IP address |
| `raspi_ssh_port` | per Pi | per Pi | per Pi | SSH port (DB default 22; Pis set up with Ansible: 8910) |
| `raspi_ssh_user` | per Pi | per Pi | per Pi | SSH username (DB default `pi`; Pis set up with Ansible: `www-data`) |

`overlay_height` and `overlay_position` are written to the configuration but not used by the text overlay:
the text always sits in the bottom left, and the font size follows the camera height.

### Configuring via Admin UI

1. Navigate to **Admin → Stream Configurations**
2. Find the configuration for your table
3. Click **Edit**
4. Set the parameters:

   **For 720p (Recommended)**:
   ```
   Camera Width: 1280
   Camera Height: 720
   Camera FPS: 30
   Video Bitrate: 2500
   Audio Bitrate: 128
   Raspberry Pi IP: 192.168.2.216  (club network)
   SSH User / Port: as for this Pi (Ansible: www-data / 8910)
   Overlay Enabled: ✓ Yes
   ```

   **For 360p (Low bandwidth/testing)**:
   ```
   Camera Width: 640
   Camera Height: 360
   Camera FPS: 30
   Video Bitrate: 1000
   Audio Bitrate: 128
   Raspberry Pi IP: 192.168.2.216  (club network)
   SSH User / Port: as for this Pi (Ansible: www-data / 8910)
   Overlay Enabled: ✓ Yes
   ```

5. Click **Update**. If the stream is running, this currently only **stops** it (see
   [Admin Dashboard Monitoring](#admin-dashboard-monitoring))
6. Use **Start** button to begin streaming

### Configuring via Rails Console

```ruby
# Connect to production server

  audio_bitrate: 128,
  overlay_enabled: true,
  raspi_ip: '192.168.2.216',
  raspi_ssh_port: 8910,        # as for this Pi
  raspi_ssh_user: 'www-data'   # as for this Pi
)

# OR update settings for 360p (low bandwidth/testing)
config.update!(
  camera_width: 640,
  camera_height: 360,
  camera_fps: 30,
  video_bitrate: 1000,
  audio_bitrate: 128,
  overlay_enabled: true,
  raspi_ip: '192.168.2.216',
  raspi_ssh_port: 8910,

)

# Verify
config.reload
puts "Resolution: #{config.camera_width}x#{config.camera_height} @ #{config.camera_fps}fps"
puts "Bitrate: #{config.video_bitrate}k"
puts "Pi: #{config.raspi_ssh_user}@#{config.raspi_ip}:#{config.raspi_ssh_port}"
```

## Raspberry Pi Setup

### Prerequisites

No Carambus repository is needed on the Pi. Everything the Pi needs comes from the Location Server:

```bash
# On the Location Server, in the deploy directory
cd /var/www/<basename>/current
export RASPI_SSH_USER=www-data RASPI_SSH_PORT=8910   # as for this Pi

# Installs packages, carambus-stream.sh, carambus-overlay-updater.sh and the systemd units
RAILS_ENV=production bundle exec rake "streaming:setup[192.168.2.216]"

# Checks packages, directories, script, unit, camera and network
RAILS_ENV=production bundle exec rake "streaming:test[192.168.2.216]"
```

The unit `carambus-stream@.service` runs as user `pi` (`User=pi` in `bin/carambus-stream.service`); on a Pi
without that user systemd refuses to start it.

### Update Script and Configuration

To bring a changed `bin/carambus-stream.sh` to the Pi, run `streaming:setup` again from the Location Server
after the server deploy (see above). The configuration file is rewritten by every **Start** in the admin
dashboard.

Verify the unit template exists:
```bash
ssh -p 8910 www-data@192.168.2.216
ls -l /etc/systemd/system/carambus-stream@.service
```

### Manual Configuration (if not using admin dashboard)

⚠️ **Note**: Admin dashboard will overwrite this file when starting stream!

The file name uses the table's database ID. For the table with `id: 2, name: "Tisch 6"`:

```bash
sudo nano /etc/carambus/stream-table-2.conf
```

The format is the one `StreamControlJob#generate_config_file` writes. `RTMP_URL` is required;
`carambus-stream.sh` aborts without it ("RTMP_URL not set"). Example for 720p:

```bash
# Carambus Stream Configuration for Table ID 2 (Tisch 6)

# Stream Destination
STREAM_DESTINATION=youtube
RTMP_URL=rtmp://a.rtmp.youtube.com/live2/<your-youtube-stream-key>

# Camera Settings
CAMERA_DEVICE=/dev/video0
CAMERA_WIDTH=1280
CAMERA_HEIGHT=720
CAMERA_FPS=30

# Overlay Settings
OVERLAY_ENABLED=true

# Quality Settings
VIDEO_BITRATE=2500
AUDIO_BITRATE=128

# Metadata
TABLE_ID=2
TABLE_NAME="Tisch 6"
LOCATION_MD5=<your-location-md5>
SERVER_URL=http://<server>:<webserver_port>
```

For 360p change `CAMERA_WIDTH=640`, `CAMERA_HEIGHT=360` and `VIDEO_BITRATE=1000`. The generated file
contains further keys (`OVERLAY_URL`, perspective and manual camera values); without them the script uses its
defaults.

### Finding Your Location MD5

```ruby
# In Rails console
location = Location.find_by(name: "BC Wedel 61 Vereinsheim")
puts location.md5
```

Or from URL when viewing scoreboard:
```
http://bc-wedel.duckdns.org:3131/locations/[LOCATION_MD5]/scoreboard?table_id=2
```

## Deployment Steps

### Production Deployment Checklist

#### 1. Server-Side (bc-wedel.duckdns.org:3131)

✅ Deploy latest code (done by the operator, from a checkout; no `git pull` on the server):
```bash
bin/rails "scenario:deploy[carambus_bcw]"
```

✅ Verify endpoint works:
```bash
curl -si "http://bc-wedel.duckdns.org:3131/locations/[MD5]/scoreboard_text?table_id=2"
```

Expected output:
```
T6 • LIVE
▶ Player1:  50 (2)
  Player2:  13
```

A `403 Forbidden` means the nginx bot block rejects `curl/…` user agents (only `/versions/` is exempt,
`templates/nginx/carambus_bot_block.conf`). The Pi's own `curl` is affected the same way; the overlay then
stays at "Loading...".

#### 2. Configure Stream via Admin Dashboard

✅ Open admin interface: `http://bc-wedel.duckdns.org:3131/admin/stream_configurations`

✅ Edit Table 6 configuration:
- Set camera resolution: **1280x720 @ 30fps**
- Set video bitrate: **2500 kbps**
- Set Raspberry Pi IP: **192.168.2.216**
- Enable overlay
- Save configuration

#### 3. Raspberry Pi Setup (when at club)

✅ From the Location Server, install or update the streaming files on the Pi (see
[Prerequisites](#prerequisites)):
```bash
RAILS_ENV=production bundle exec rake "streaming:setup[192.168.2.216]"
RAILS_ENV=production bundle exec rake "streaming:test[192.168.2.216]"
```

✅ Verify camera:
```bash
ssh -p 8910 www-data@192.168.2.216
v4l2-ctl --device=/dev/video0 --list-formats-ext
```

#### 4. Start Streaming

**Option A: Via Admin Dashboard (Recommended)**
1. Open admin interface
2. Find Table 6 configuration
3. Click **Start** button
4. Monitor status (should show 🟢 Active)

**Option B: Manual (for testing)** — the configuration must already be deployed:
```bash
ssh -p 8910 www-data@192.168.2.216
sudo systemctl start carambus-stream@2.service    # 2 = table_id of "Tisch 6"
sudo systemctl status carambus-stream@2.service
```

#### 5. Verify Stream

✅ Check YouTube Studio after 30-60 seconds
- Resolution should show **720p**
- Keyframe interval: **2 seconds** (no warning)
- Stream delay: **~5-8 seconds**

✅ Check overlay text appears:
```
T6 • LIVE
▶ Gernot:  52 (2)
  Jörg:    15
```

✅ Test live updates:
- Enter score in scoreboard
- Overlay should update within **~1 second**
- Numbers should be **right-aligned**
- Current inning balls in **parentheses**

## Monitoring & Troubleshooting

### Admin Dashboard Monitoring

The dashboard provides:
- **Real-time status** (Active, Inactive, Error)
- **Health checks** every 30 seconds while the Stream Configurations page is open, and via the
  **Health-Check** button (❤️). There is no background schedule
- **Start/Stop controls**
- **Restart** (🔄): currently only **stops** a running stream (`StreamConfiguration#restart_streaming`);
  click **Start** afterwards. Saving the configuration while the stream runs behaves the same way
- Pi logs are **not** shown in the dashboard (planned; `fetch_recent_logs` is a placeholder). Read them on
  the Pi (see below)

### Manual Monitoring on Pi

```bash
# Check service status (start/stop/restart events)
sudo systemctl status carambus-stream@<table_id>.service

# Watch live logs (script and FFmpeg write here, not to the journal)
tail -f /var/log/carambus/stream-table-<table_id>.log
tail -f /var/log/carambus/stream-table-<table_id>-error.log

# Check FFmpeg is running
ps aux | grep ffmpeg

# Check which server the Pi fetches the text from
grep SERVER_URL /etc/carambus/stream-table-<table_id>.conf

# Test text endpoint (same request the Pi makes)
curl -si "http://bc-wedel.duckdns.org:3131/locations/[MD5]/scoreboard_text?table_id=2"
```

The text file itself lives in the service's private `/tmp`. If needed, find it with
`sudo sh -c 'ls /tmp/systemd-private-*-carambus-stream@<table_id>.service-*/tmp/'` (the inner directory is
only readable by root, so the glob must run under `sudo`).

### Common Issues

#### Stream Not Starting

**Symptom**: Admin dashboard shows "Failed to start" or "Authentication failed"

**Check**:
1. SSH connectivity from the server to the Pi, as the service user and with the configured user/port:
   ```bash
   cd /var/www/<basename>/current
   RAILS_ENV=production bundle exec rake "streaming:ssh_test[2]"
   ```
2. Camera not in use:
   ```bash
   lsof /dev/video0
   ```
3. Configuration file deployed:
   ```bash
   cat /etc/carambus/stream-table-2.conf
   ```
4. Error log on the Pi: `tail -n 50 /var/log/carambus/stream-table-2-error.log`

#### Overlay Not Showing

**Symptom**: Stream works but no overlay text, or only "Loading..."

**Check**:
1. `SERVER_URL` in `/etc/carambus/stream-table-2.conf` points to the server, not to `localhost`
   (otherwise set `STREAMING_SERVER_URL`, see [How Admin Dashboard Controls Streaming](#how-admin-dashboard-controls-streaming))
2. Background curl process running:
   ```bash
   ps aux | grep curl | grep scoreboard_text
   ```
3. Server endpoint accessible from Pi, without 403 from the bot block:
   ```bash
   curl -si "http://bc-wedel.duckdns.org:3131/locations/[MD5]/scoreboard_text?table_id=2"
   ```

#### Text Not Updating

**Symptom**: Overlay frozen on old score

**Check**:
1. Background curl still running (might have crashed)
2. Restart service:
   ```bash
   sudo systemctl restart carambus-stream@<table_id>.service
   ```

#### Blurry or Pixelated

**Symptom**: Low quality stream

**Fix**: Increase resolution/bitrate via admin dashboard:
- For 720p: 2500 kbps
- For 1080p: 4500 kbps (may overload Pi4)

#### YouTube Keyframe Warning

**Symptom**: "Verwende eine Keyframe-Frequenz von vier Sekunden oder weniger"

**Fix**: Should be automatic (script sets `-g 60` for 2-second keyframes at 30fps)

If still appears, check FFmpeg command:
```bash
ps aux | grep ffmpeg | grep -o '\-g [0-9]*'
# Should show: -g 60
```

### Performance Monitoring

```bash
# CPU usage
htop

# FFmpeg stats (FFmpeg output goes to the log file, not to the journal)
tail -f /var/log/carambus/stream-table-<table_id>.log | grep fps=

# Network bandwidth
iftop -i wlan0  # or eth0
```

### Stopping the Stream

**Via Admin Dashboard**:
- Click **Stop** button

**Manual**:
```bash
sudo systemctl stop carambus-stream@<table_id>.service
```

## Technical Notes

### TABLE_ID in File Names

All file names and the service instance use the Rails database ID (`Table.id`). There is no `TABLE_NUMBER`.

Example:
- Table in database: `id: 2, name: "Tisch 6"`
- Config file: `/etc/carambus/stream-table-2.conf`
- Text file: `/tmp/carambus-overlay-text-table-2.txt` (private `/tmp` of the service)
- Service: `carambus-stream@2.service`
- Fetches data: `?table_id=2`
- The overlay text shows the number from the name: `T6 • LIVE`

### Font Sizing

The script auto-scales font based on resolution:
- **360p**: 16px
- **720p**: 24px
- **1080p**: 32px

### Text Format

Current format (monospace font for alignment):
```
Line 1: T6 • LIVE
Line 2: ▶ Name1:  Score1 (InningBalls)
Line 3:   Name2:  Score2
```

- Right-aligned scores
- Current inning balls in parentheses (only when > 0)
- Active player indicator: `▶`
- Inactive player: two spaces `  `

### Resolution Recommendations

| Resolution | Bitrate | CPU | Quality | Recommended |
|------------|---------|-----|---------|-------------|
| 360p (640x360) | 1000k | Low | Poor text | ❌ No |
| 720p (1280x720) | 2500k | Medium | Good | ✅ **Yes** |
| 1080p (1920x1080) | 4500k | High | Excellent | ⚠️ May lag |

**Production recommendation**: **720p @ 30fps @ 2500k** - Best balance for Pi4.

## Security Notes

### SSH Authentication

The job and the rake tasks authenticate in this order:

1. `RASPI_SSH_PASSWORD`, if set (takes precedence)
2. `RASPI_SSH_KEYS`, a comma-separated list of key paths
3. otherwise the default keys `~/.ssh/id_rsa`, `id_ed25519`, `id_ecdsa`, `id_dsa` of the calling user

For the admin dashboard, the calling user is the Carambus service (`www-data`), and only variables from
`/etc/<basename>.env` count; a shell `export` affects only rake calls from that shell. Using a key:

1. Generate key on server (as `www-data`):
   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/carambus_streaming
   ```

2. Add `~/.ssh/carambus_streaming.pub` to `~/.ssh/authorized_keys` of the SSH user on the Pi
   (`rake "streaming:ssh_test[<table_id>]"` prints the key and the commands)

3. Point the service at it, in `/etc/<basename>.env`, then restart `puma-<basename>`:
   ```bash
   RASPI_SSH_KEYS=~/.ssh/carambus_streaming
   ```
   With a default key name (`~/.ssh/id_ed25519`) this step is not needed. `RASPI_SSH_PASSWORD` must not be set,
   otherwise it wins.

### Network Security

- Raspberry Pi is only accessible within club LAN (192.168.2.x)
- No direct internet exposure
- Server initiates all connections (outbound SSH)
- YouTube stream key should be kept secret. It is encrypted in the database, but on the Pi it is stored in
  plain text in `/etc/carambus/stream-table-<table_id>.conf` (part of `RTMP_URL`, file mode 644)
